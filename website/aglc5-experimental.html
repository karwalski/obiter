Experimental AGLC5 Citation Forms

AGLC4, the current edition of the Australian Guide to Legal Citation (2018), has no rule for generative AI output, datasets, software or archived web pages. This page sets out the interim forms Obiter uses for them, the evidence behind each one, the decisions and corrections made along the way, and what will change when AGLC5 is published.

Matthew Watt · Updated 24 September 2026 · Open letter to the AGLC5 Committee

1. Status of AGLC5 (as at 24 September 2026)

AGLC5 has not been published, and AGLC4 remains the current edition. The AGLC5 Committee is run by the Melbourne University Law Review and the Melbourne Journal of International Law. Its page says it consulted from 2023 to 2026, is now considering the outcomes, and is not accepting further feedback. It gives no date, no draft and no ISBN. The page's last-modified date is 12 May 2026.

The page has also changed in ways that are easy to miss:

  • It now describes consultations for a prospective new edition. In March 2025 it said the journals were preparing a new edition for publication.
  • The feedback address has been removed.
  • The list of the Committee's aims has been removed. The last archived copy that shows the list (Wayback Machine, 24 March 2025) gives seven aims, not the six usually cited:
    1. making the guide more comprehensive
    2. improving its structure
    3. simplification and usability
    4. citing First Nations materials and decolonising scholarship
    5. encouraging use of the guide by practitioners
    6. updating the internet-materials rules for the digital age, including artificial intelligence
    7. gender-inclusive and culturally sensitive language and examples

We cannot date the rewrite, because the archive has no copy of the page after March 2025. It may just be tidying up after the consultation closed. The accurate statement is that the aims are no longer published, not that they have been dropped.

Checking the page yourself: the Committee page blocks automated requests (HTTP 403), so a scripted check can wrongly report "no change". Obiter's watcher treats a blocked request as unreadable and says so, rather than as unchanged.

2. How experimental forms are labelled

Every form on this page is an Obiter extension. None of them is an official AGLC4 form. In the add-in each one carries the badge Experimental · pending AGLC5 (not an official AGLC4 form) in the source-type picker and the form header, with a note on its basis. The rules for this are set by DECISION-036:

  • Data-driven. A source type is experimental because its metadata says so (provenance: experimental_pending_aglc5), not because of hard-coded screens.
  • Kept out of conformance claims. Experimental forms are excluded from Obiter's AGLC4 conformance count and from any claim that Obiter produces AGLC4 output.
  • No stranded documents. When AGLC5 is published, each form is either mapped to the new rule or retired. Citations already in documents keep rendering (see section 9).

4. Generative AI output in detail (EXP-1, 6–13)

AGLC4 was published in 2018 and has no generative AI rule. Australian law libraries cite AI output by analogy to written correspondence (rule 7.12). They credit this to interim guidance from the Melbourne University Law Review editors, which they call interim and not official. Every trace of that guidance is a library paraphrase. MULR's own text has not been found.

What the library guides say (checked 24 September 2026)

Every guide checked uses one template: Output from [program], [creator] to [recipient], [full date]. The developer follows the program after a comma, with no comma before "to". Only Canberra differs, and none says "Correspondence from". The guides copy one another, so they show one convention repeated, not a dozen independent authorities. No Australian law journal footnote citing a specific AI output has been found. In New Zealand, NZLSG 3 is silent (Auckland). Canterbury adapts NZLSG r 7.6 with a similar "Output from" form.

Later references and the bibliography entry:

Output from Claude (n 1)
Output from Copilot to Citizen (n 1)

Anthropic, Claude (Claude Opus 4.8) to the author, Output, 24 September 2026

  • Wording (EXP-9): "Output from", as every guide has it. A document can keep Obiter's earlier "Correspondence from" through a setting. Stored citations are never changed, so the switch can be reversed.
  • Developer (EXP-6): optional. It follows the program and model with a comma before it and none after, as the guides do. AGLC4's only similar example (ex 95, a place after the sender) has commas on both sides. We recorded it and chose library practice.
  • Recipient (EXP-7): optional. It defaults to "the author".
  • Prompt note (EXP-8, EXP-12): off by default. When on, it appears in the first citation only, with the comma the guides use.
  • Later references (EXP-10): the type word and program, plus the recipient's surname when a recipient is named. This follows Obiter's correspondence short form.
  • Bibliography (EXP-11): listed under Other, developer first.
  • Model version: an Obiter addition. Neither the library template nor OSCOLA has one.

OSCOLA 5 form (r 3.7.13)

OSCOLA 5 treats the AI as the author. Any instructions follow after "response to", then the developer, then the date in brackets. The rule has no URL and no model version. Obiter now follows it (EXP-13):

ChatGPT, response to ‘Explain how artificial intelligence works’, OpenAI (16 July 2023)
ChatGPT (n 1)

If no instructions were given, Obiter omits that element ("ChatGPT, OpenAI (date)"). The rule does not show this case, so it is a judgement call.

Found while checking our own work: the August 2026 release left out the developer and always wrote "to the author" (fixed by EXP-6 and EXP-7). Later references to AI output had lost their identifier, and the AGLC bibliography entry was empty (fixed by EXP-10 and EXP-11). The OSCOLA form had the wrong element order, added a URL and printed dates in ISO format (fixed by EXP-13).

5. Court rules on generative AI (not citation rules)

Australian courts and tribunals have issued practice notes and directions on generative AI. They impose duties on the person responsible for a document: check that cited authorities exist and support the point, disclose AI use where required, and do not rely on an AI tool alone to check AI output. None of them prescribes a form for citing AI output. Obiter shows them as reminders in court mode, labelled as practice-direction guidance, and never as AGLC rules.

  • New since July 2026: the Administrative Review Tribunal (Use of Generative AI) Practice Direction 2026, signed by the President on 20 August 2026 and in force from signature. It is adapted from the Federal Court's note and now appears in Obiter's court mode.
  • Also on 20 August 2026: the Tribunal's Expert Evidence Practice Direction 2026 was amended (cll 3.5A–3.5D). An expert report must now say whether it contains AI content, identify that content and the tools used, and certify that the expert checked it. Court mode cites this as well. The Common Procedures Practice Direction 2026 has no citation requirements; its only AI clause bars AI recording agents in hearings without permission.
  • Unchanged: the Federal Court's GPN-AI (16 April 2026), NSW Supreme Court Practice Note SC Gen 23 (in force 3 February 2025), and Victoria's SC Gen 25 (14 May 2026). Queensland, South Australian, Western Australian and Family Court instruments are also covered.
  • Design limit for software: SC Gen 23 bars using an AI tool as the only way of checking citations, and the tribunal's direction bars relying on a tool to check its own output. Obiter's citation checker therefore helps the author check a citation; it never claims to do the check for them.

6. Corrections and contradictions

The September 2026 review checked 25 claims against their primary sources: 20 held up and 5 did not. The corrections below are recorded in DECISION-041.

Corrections and contradictions
Earlier position or claim What the evidence shows
The Committee's six published aims are its current position The aims are no longer on the Committee page. The last archived list (March 2025) has seven. Cite that archived copy and say the aims were withdrawn.
The open letter's correspondence window remains open The Committee lists no contact and is not accepting feedback. We withdrew that statement.
OSCOLA is published under a Creative Commons licence, so it is a precedent for an open AGLC5 licence Refuted. The OSCOLA 5 PDF has no licence statement. OSCOLA shows that a free full text can sit alongside a commercial print edition (Hart). It is a precedent for open access, not for permission to reuse the text.
AGLC4's lack of rules on checking authorities or disclosing AI use is an AGLC4 defect Not so. These duties come from the courts. No citation guide covers them, including OSCOLA 5 and the NZ Law Style Guide. The real gap for AGLC5 is a citation form for AI output.
The ART direction requires external sources to be traceable Refuted. It has no such clause, so it cannot justify archive fields. Link-rot practice does (EXP-4).
NSW SC Gen 23 sets out a metadata model for AI use by experts Refuted, and not used as a basis for any form.
The Federal Court's GPN-AI paragraphs can be cited from its notice to the profession The notice is a one-page announcement. Cite the practice note itself (/practice-notes/gpn-ai).
Obiter's "Correspondence from" follows MULR's interim guidance The library guides that relay that guidance all say "Output from". So does the University of Melbourne's own Re:cite page. We changed the default and kept the old form as a document setting.
Obiter's OSCOLA form, "ChatGPT (OpenAI), 'prompt' (response generated date) <url>" This did not match r 3.7.13. It now follows the rule's example exactly.
OSCOLA 5 r 3.7.13 has a model-version element It does not. An Obiter code comment said otherwise and has been corrected.
OSCOLA 5's replacement of "ibid" is fully rule-based Partly. It removes the ambiguity of "ibid", but writers still choose the short form. A realistic AGLC5 request is to remove that ambiguity, not to make every choice mechanical.

7. Where AGLC4 is silent or inconsistent

The following are places where AGLC4's rule text and examples leave a question open, and a working tool had to pick an answer. AGLC5 could settle each one either way. The decisions are in the project's decision log.

  • Amending legislation (DECISION-008). The guide does not say clearly whether to cite the amending Act or the principal Act. Obiter cites the single Act by default; the combined form is opt-in.
  • Em-dash spacing (DECISION-013). The guide bans spaced em-dashes in citations but uses them in its own headings. Obiter applies the ban only inside citations.
  • Ampersands in journal titles (DECISION-014). The rule says to follow the title page, but an example changes "&" to "and". Obiter follows the rule and keeps the ampersand.
  • Ebooks (DECISION-019). The guide has no ebook rule. Obiter formats an ebook as a book plus a URL.
  • Partial dates (DECISION-020). The template asks for a full date, but an example uses a partial one. Obiter accepts a partial date where that is all the source gives.
  • Italics inside titles (DECISION-021). Obiter marks italic words within a title with a simple inline marker.
  • US constitutional numerals (DECISION-027). The guide does not say Roman or Arabic. Obiter keeps the numerals as entered.

8. Open questions

  • What exactly does MULR's own interim guidance say? We know it only through library guides.
  • Has any Australian law journal printed a footnote citing AI output, and does it put a comma after the developer?
  • How should OSCOLA 5 r 3.7.13 read when no instructions were given?
  • What do the guides not yet checked (Monash, UNSW, Sydney, RMIT and others) say?
  • Should NZLSG documents use Canterbury's adapted form? NZLSG 3 is silent, and Obiter currently renders the AGLC form under NZLSG.
  • Has any Australian institution followed OSCOLA and treated the AI as the author, instead of using the correspondence analogy? None has been found so far.
  • When and why was the Committee page rewritten, and does it signal a change in AGLC5's scope or timing?

Researchers and editors can respond through the contact page or on GitHub.

9. AGLC5 adoption backlog

This is the list of work to do when AGLC5 is published, or if Obiter is given pre-release access to a draft. The engine already records the edition on every citation. AGLC5 rules will be added alongside the AGLC4 rules, and AGLC4 documents will keep rendering under AGLC4.

Planned handling of each experimental form on AGLC5 publication
Form If AGLC5 adopts a matching rule If AGLC5 differs If AGLC5 is silent
Generative AI (EXP-1, 6–13) Map the fields to the official rule and remove the badge. AGLC4 documents keep their form. Add an AGLC5 formatter and re-key the stored fields. The badge stays until everything maps. Keep as an Obiter extension, still badged
Dataset, software (EXP-2, 3) Promote to official types and remove the badge Adjust element order and labels Keep experimental
Archive fields (EXP-4) Fold into the official archived-source rule Adjust the rendering Keep experimental
AI-layer marker (EXP-5) Use the official marker wording Adjust Keep experimental

Steps on publication day

  1. Compare AGLC5 with AGLC4 rule by rule, using Obiter's AGLC4 critique as the checklist of expected changes.
  2. Add the AGLC5 rules alongside the AGLC4 rules without changing the AGLC4 ones.
  3. Settle each experimental form using the table above. Stored data is re-keyed, never deleted. Any field that cannot be mapped is kept on the record.
  4. Mark each form AGLC5 adopts as official. Its badge and conformance exclusion then drop away automatically.
  5. Recount conformance, then update the extensions register, this page and the open letter.
  6. Run the full test suite, plus a test that an AGLC4 document containing every experimental field opens and renders unchanged.

Known technical debt

  • Two generative AI wordings: documents can still use "Correspondence from". When AGLC5 is published, both map to the official form, and the setting is then retired.
  • The watcher depends on a text proxy: the AGLC5 page blocks direct requests, so the monthly check reads it through a proxy. If both paths fail, the check reports unreadable rather than unchanged.
  • The Copilot companion's rule export is paused with that product and still describes the pre-2026 generative AI form.
  • The seven silent-rule decisions in section 7 need confirming or reversing against AGLC5.

Pre-release access. If the Committee shares a draft, Obiter's rule tests can run the draft's examples against the engine and report which forms change before publication. The open letter sets out this offer.
