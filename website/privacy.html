Privacy Policy

How Obiter handles your data. The short version: it mostly does not.

Last updated: 22 July 2026

Who We Are

Obiter is developed and maintained by Matthew Watt, an individual developer based in Australia. The project website is obiter.com.au. Obiter is a free, open-source Microsoft Word add-in that automates AGLC4 citation formatting.

Data Stored in Your Document

When you use Obiter to insert citations, the citation metadata is stored in a Custom XML Part within the .docx file itself. This data never leaves your document. It includes: source type, author names, titles, years, report series, pinpoints, and short titles.

Obiter also keeps periodic backup snapshots of your citation library inside the same Custom XML Part, and stores short fingerprint values (hashes) in footnote content-control titles so it can detect manual edits. These, too, live entirely inside the .docx file.

All citation data remains under your full control. It is saved as part of your Word document and is not transmitted to any server during normal add-in operation.

Data Stored Locally

The following preferences are stored in your browser's localStorage on your device:

  • Template preferences
  • AGLC version selection
  • Branding preferences
  • LLM API keys (if configured)

You can delete all stored API keys at any time using the Remove stored keys option in Settings.

Data stored in localStorage is not transmitted to Obiter servers, with one exception: if you configure a custom LLM endpoint, your API key accompanies each relayed request through the Obiter server. See "Third-Party LLM Integration" below.

Optional Obiter Accounts

An Obiter account is entirely optional. Obiter works fully without an account, and the "no account required, citation data never leaves the document" promise is unchanged: using your own API key without an account (BYOK) remains fully supported. You only create an account if you want your settings to roam between devices, or to store your LLM API keys server-side instead of on each device.

When you do create an account, we store on the obiter.com.au server:

  • Your email address (for sign-in, verification, and account notices).
  • Your password as an argon2id hash — never the plain password, and the hash is not reversible.
  • Your LLM API keys, if you choose to store them, encrypted at rest with AES-256-GCM.
  • Your synced settings (LLM configuration without any key, template preferences, source toggles, and similar device preferences).
  • Account audit events (for example sign-in, key save, settings update) recorded with the action, a timestamp, and a one-way hashed IP address — never your raw IP.
  • If you enable multi-factor authentication, your TOTP secret, encrypted at rest.

An account never stores your citation data or your documents. Those stay inside your .docx file, as described above, and are never synced to an account.

Stored API keys are write-only. Once a key is saved, it is never returned to any browser again. It is decrypted only in-process, on the server, at the moment the Obiter relay makes a request to your chosen provider on your behalf; no endpoint exists that reads a stored key back out. The task pane only ever sees the provider name and the last four characters, for display.

Your data rights. While signed in, you can export a JSON copy of your account data (your email, settings, and audit trail) from Settings, and you can delete your account from Settings after a re-authentication step. Deleting your account immediately purges your synced settings and stored keys, revokes your sessions on all devices, and anonymises your account record; both export and deletion are recorded in the audit trail.

Retention. Account data is kept while the account is active. Audit events are retained for up to 12 months and then pruned. Deleted accounts are anonymised rather than kept, and their settings and stored keys are removed at deletion time.

Anonymous Load Counting

When you open Obiter, the add-in sends a single anonymous load event to obiter.com.au. This event contains only:

  • Obiter version number
  • Microsoft Word version
  • Operating system / platform
  • A randomly generated device identifier (a UUID stored in your browser — it is not derived from any personal data)

This data is used solely to understand how many people use Obiter and on which platforms. No personal data, document content, IP addresses, or user identifiers are collected. The load event is sent once per session (each time you open the task pane). You cannot be identified from this data.

Third-Party LLM Integration (Optional, User-Controlled)

LLM features are entirely optional and disabled by default. Users must explicitly enable LLM integration and provide their own API key before any data is sent to a third-party provider.

When enabled, the following data may be sent to the user's chosen LLM provider (OpenAI, Anthropic, Google Gemini, xAI Grok, DeepSeek, or a custom endpoint):

  • User-selected text only. Only text that you explicitly select and submit is sent. Obiter never sends your entire document, unseen content, or background data to any LLM.
  • Citation verification: the selected citation text and relevant AGLC4 rule text.
  • Citation parsing: a raw citation string pasted by you.
  • Short title suggestion: the citation's title and source type.
  • Source type classification: a user-provided description of a source.
  • Future features (e.g., "find me a reference") will always be limited to user-selected text that you explicitly review and approve before submission.

API keys are stored locally in your browser and are never written to your document. Requests to the built-in providers (OpenAI, Anthropic, Google Gemini, xAI Grok, DeepSeek) go directly from your browser to the provider you have selected — no request data, API keys, prompts, or responses pass through the Obiter server.

Custom endpoints are the exception. The add-in's security policy only permits direct connections to the built-in providers, so requests to a custom (user-configured) endpoint are relayed through the Obiter server (obiter.com.au). Each relayed request contains the prompt text, your API key, and the address of your chosen endpoint. The server forwards the request to that endpoint and returns the response to you. It does not log, store, or retain any part of the request or response, including the API key. If you prefer that no LLM traffic transit the Obiter server, use one of the built-in providers instead.

Obiter has no access to your LLM provider account or usage data.

You can disable LLM integration at any time in Settings.

External API Search (Optional, Disabled by Default)

Obiter includes an optional typeahead search feature for cases and legislation. This feature is disabled by default and must be explicitly enabled in Settings. You can choose which search providers to use individually: AustLII, Jade.io, and the Federal Register of Legislation.

When enabled, search queries are routed through the Obiter proxy server (obiter.com.au) to bypass browser security restrictions, and are forwarded only to the providers you have selected. The proxy does not log, store, or retain search queries. Search is triggered only by your typing in a citation field — no automatic or background searches are performed.

Error Reporting (Optional)

Obiter includes an optional error reporting feature that allows users to send diagnostic information to the developer when an unexpected error occurs in the add-in. Error reporting is entirely voluntary and is never sent automatically.

When an error occurs, users are shown the option to report it. If the user chooses to send a report, the following data may be included:

  • The error message and stack trace
  • The action that caused the error (e.g., "Insert Citation")
  • Microsoft Word version and operating system
  • Obiter version number
  • The citation standard and writing mode in use
  • Form data (only if the user explicitly checks the "Include current form data" checkbox)

No personal data, document content, or API keys are collected. Error reports are stored on the Obiter server and are used solely for debugging and improving the add-in. Reports can be deleted on request via the contact form.

Update Check

Once every 24 hours, the add-in queries GitHub's public releases API to check whether a newer version of Obiter is available. The request is unauthenticated and contains no personal data or identifiers. Like any web request, it is subject to GitHub's privacy statement.

Website Contact Forms and Signatures

Contact form submissions (name, email, message) are stored in a database on the Obiter server and forwarded via email to the developer.

Open letter signatures (name, title, institution, email) are stored in a database. Email addresses are used for verification only and are never displayed publicly. Signatures can be withdrawn at any time by contacting the developer.

Security

A technical description of Obiter's data flows and security controls is published in the project's threat model on GitHub. Release downloads can be verified against the SHA256SUMS.txt file attached to each GitHub release.

Children

Obiter is not directed at children under 13. We do not knowingly collect personal information from children.

Changes to This Policy

We may update this privacy policy from time to time. Changes will be posted on this page with an updated "last updated" date.
